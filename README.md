# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Тесты

```sh
node --test server.test.mjs
```

Устанавливать пакеты и отдельно запускать сервер для тестов не нужно: тесты используют встроенный `node:test` и поднимают серверы на свободных локальных портах. Проверяются HTTP-статусы и тела ответов, все пять сценариев сбоя имитатора, валидация ввода и ответа модели, восстановление после ошибки и таймаут даже при игнорировании сигнала отмены.

## Что реализовано

- `server.mjs` отдельно проверяет входной JSON до вызова AI: поле `text` должно быть строкой с непробельными символами. Ошибочный ввод получает HTTP 400 и `{"status":"invalid_input"}`.
- После вызова AI сервер разбирает JSON и проверяет объект, допустимую тему (`delivery`, `pricing`, `other`) и непустой строковый черновик. Ответ API собирается только из проверенных полей: лишние поля модели не могут подменить `status`.
- Ожидание AI ограничено 300 мс через `Promise.race`; при истечении срока также отправляется сигнал отмены. Таймер освобождается и при успехе, и при ошибке. Любой сбой AI возвращает HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`.
- Страница показывает русское название темы и черновик как текст. При новом разборе предыдущие тема и черновик сразу очищаются. При сбое менеджер видит инструкцию разобрать заявку вручную, а исходный текст заявки сохраняется.
- Пустой ввод проверяется и на странице. На время запроса повторная отправка и редактирование заявки заблокированы; после завершения управление восстанавливается. Сетевая ошибка, некорректный ответ API или ожидание соединения дольше 5 секунд также переводят интерфейс в ручной разбор.
- `mock-ai.mjs` оставлен без изменений. Внешних AI-запросов, ключей и новых зависимостей нет.

## Проверка страницы перед сдачей

1. Запустите сервер и отправьте `Когда доставка?`. Должны появиться тема «Доставка» и непустой черновик.
2. Отправьте `[timeout]`. Примерно через 300 мс должно появиться сообщение о ручном разборе; предыдущие тема и черновик должны исчезнуть. Текст заявки должен остаться в поле.
3. Повторите последовательность «успех → сбой» с `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`.
4. После успешного разбора отправьте пустую строку или пробелы: предыдущий результат очищается, появляется просьба ввести текст, сетевой запрос не отправляется.
5. После успешного разбора остановите сервер и отправьте новую заявку: страница должна показать ручной разбор и очистить результат. После запуска сервера снова можно отправить заявку.

## Польза для менеджера

Менеджер быстрее получает тему и черновик ответа, а при сбое продолжает работу вручную без риска взять черновик от предыдущей заявки. Эффект можно измерить изменением медианного времени от открытия заявки до проверенного ответа; дополнительно учитывать долю ручного разбора и долю черновиков, потребовавших исправления.

## Использование AI

Для анализа, реализации, тестов и документации использован OpenAI Codex (GPT-6). Агент выполнил HTTP-тесты и проверку интерфейса в браузере, включая последовательность «успех → сбой», сетевые ошибки, повторную отправку и очистку черновика. Это описание работы агента; самостоятельные проверки кандидата следует указать в PR после собственного запуска команд и сценариев выше.

Ниже сохранены исходные условия задания.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

После сдачи бот может задать один-два коротких вопроса по вашему коду. Используйте учебные данные. Если не уложились по времени, отметьте незавершённые части в PR.
